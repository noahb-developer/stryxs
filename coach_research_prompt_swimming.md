## ROUND 1 (new conversation)

Key every rule to three experience tiers (beginner / intermediate / advanced) and give a DEFAULT value for every range. Reminder of the athlete data the app has, so every rule keys off real fields: CSS (critical swim speed, pace per 100 m), recent swims with per-100 m pace / distance / duration / average HR (if a waterproof monitor is worn, often absent) / stroke count or SWOLF (if available) / pool-vs-open-water flag, experience tier, available training days, weekly hours or weekly distance, equipment (pool access + pool length 25 m vs 50 m, open-water access, pull buoy / paddles / fins / snorkel / kickboard, wetsuit), age / sex, injuries (shoulder especially), and a live training-load model (CTL fitness, ATL fatigue, TSB form, ACWR), plus completed-vs-planned sessions.

Keep every number internally consistent — I will unit-test the code against them.

9. ANTI-PATTERNS / SAFETY RULES — explicit DO-NOT rules with numbers, swimming-specific: junk-yardage / aerobic grey-zone (endless moderate swimming, never truly easy or truly race-pace), volume without technique, ramping weekly meters or paddle/pull volume too fast (swimmer's shoulder — the dominant overuse injury), neglecting recovery, all-sprint or all-easy, over-relying on fins/paddles to mask poor catch, ignoring breathing-pattern / bilateral imbalance. 10. FEASIBILITY / SANITY CHECK — given a goal (finish a 5 km open-water swim, a sub-X 1500 m, a target CSS pace, an open-water event time) + weeks-to-event + current ability, judge whether it is realistic and the minimum training (weekly meters, longest swim, weeks, key sessions/wk, technique time) it requires; how fast CSS pace and efficiency realistically improve for a beginner (large early gains from technique) vs a trained swimmer (small fitness gains) — give rates (s/100 m per block). Pair any "unrealistic" verdict with the specific lever (more weeks, more volume, more technique, more race-pace work, or a softer goal).

FORMAT: clear headers and bullets, tables for anything numeric (zone %CSS, phase durations, distance->sessions maps, pace-by-distance %, pool->open-water adjustments, confidence thresholds, CSS norms by tier/sex), explicit numbers and rules I can turn into code, mark every [DISTANCE vs SPEED vs TECHNIQUE vs FITNESS] divergence, every rule keyed to beginner/intermediate/advanced WITH a default, thorough but dense, no filler.
